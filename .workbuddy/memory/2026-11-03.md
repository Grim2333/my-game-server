## 狼美人：一夜只有一次行动（锁死规则收敛）
用户口径：手上「狼人 + 狼美人」，先魅惑、再用狼人出刀 → 此时魅惑与刀都用过，狼美人本回合不能再动。

实现：
- `Card.charmUsedTonight`（新 schema 字段，每夜 startTurn 重置）取代私有 `Set beautyCharmedTonight`，成为唯一真源。
- 新增 `beautyHasAction(card)` = `!charmUsedTonight || !wolfKnifeUsed`；`refreshBeautyActed()` 在狼刀结算后同步手牌里所有狼美人的 `acted`。
- `playCard` 入口在 `card.acted` 判断之前先拦：狼美人技能用尽 → playRejected「本夜狼美人的技能已用完」。
- 魅惑结算：`charmUsedTonight = true`，`acted = !beautyHasAction()`（刀还在 → 仍可再出刀；刀已被别人用掉 → 当场锁死）。
- `beautyAction` 的 charm 分支加守卫，禁止同一夜二次魅惑。
- 前端 `isBeauty` 改为 `(!card.charmUsedTonight || !state.wolfKnifeUsed)`；狼美人二选一弹窗里「魅惑」按钮在已魅惑时置灰。
- `cloneCard` 补拷 `charmUsedTonight`（盗贼换走狼美人时状态跟随）。

测试：新增 `狼美人：先魅惑 → 再用别的狼出刀 → 这张牌本回合彻底锁死`（含新夜重置断言）。92 passing。

## 天使重生也要算「本夜死过牌」
- 原来 `recomputeLostThisNight` 只比手牌+行动区数量有没有变少；天使重生后牌回手、还多摸一张，数量不减 → 判成"没死过"，
  流放资格拿不到。
- 改为新增 `diedThisNight: Set<sessionId>`：在 `resolveQueue` 里记录"真的走完一次死亡"——
  天使分支在 `reviveAngel` 之前 add（重生也算死过一次），正常死亡在进墓地前 add；
  守卫挡下 / 老流氓负伤在 add 之前 continue，所以不算死。入夜 `snapshotNightStart` 时清空。
- `lostThisNight = diedThisNight.has(id) || 数量变少`（保留旧判定做兜底）。
- 测试：天使被刀 → 墓地 0 张 → 天亮 lostThisNight=true → P2 白天 exile 能进结算。96 passing。

## 奇迹商人「点了神职牌没反应」排查
- 用 jsdom + 真服务器实测（临时脚本，已删）：奇迹商人进行动区后，`pendingAction = merchantBless / zone=hand`，
  神职卡渲染为 `selectable`，点击确实发出 `chooseTarget{index,side:"self"}`，服务端正常强化（猎人多带 2 人 / 女巫进入 witchBless）。
  → 链路本身没坏。
- 真正的隐患有两个：
  1. 出牌后手牌会前移，DOM 的 `data-idx` 可能仍然指向旧位置 → 点到"另一张牌"，客户端按 type 判断后静默 return（表现就是"点了没反应"）。
     修法：点击时用 `data-id` 去实时 hand 数组里重新定位 idx（不一致才回退查找）。
  2. 点到非神职牌时是静默 return，没有任何反馈。改为往事件日志写一行「⛔「X」不是神职，奇迹商人只能强化神职牌」。
- 另注意：长老/天使/白痴/盗贼/野孩子/炸弹人/老流氓/奇迹商人 在牌库里 type 都是 villager（长老靠 voteWeight 特判 2 票），
  所以按现状它们不在"神职"可强化范围内。若用户想放开，属于规则变更，需先问。

## 白狼王白天不高亮：真凶是「本夜刀已用」的残刀标记
- 现象：白天轮到自己、还没行动，白狼王依旧是灰的、还带「🔪 本夜刀已用」角标。
- 原因：`state.wolfKnifeUsed` 只在**每个黑夜回合开始**重置（startTurn 里 phase==="night" 时），
  天亮后它保留的是「最后一夜」的值。手牌渲染里那条「狼刀已用 → 其余狼牌置灰」的分支
  没有判断昼夜，于是白天把白狼王（isWolf）也当成"刀已用"灰掉了（还压过 playable 的金边）。
  因为 P1 出刀后 P2 的夜晚回合会再重置一次，所以只有"最后出刀的是后手 P2"时才稳定复现。
- 修法：该分支加 `night &&`，白天完全不生效。白狼王白天在自己的回合就会正常 `playable`（金边可点）。
- 验证：用 in-process room + jsdom 加载真实 index.html 复现（P2 出刀 → 天亮 → 渲染 P1 手牌）：
  修前 `ww:card wolf playable acted [🔪 本夜刀已用]`，修后 `ww:card wolf playable`，白天自爆正常结算。
