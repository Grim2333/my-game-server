## 2026-10-23 修复"两人加入却不开始游戏"
- 现象：两名玩家加入后始终不开局。服务端逻辑实测正常（两人 joinOrCreate 同一房间 → round=1 自动开局）
- 根因：僵尸房间/僵尸座位——浏览器刷新或断网时旧会话未走 onLeave，仍占着 maxClients=2 的名额；后续玩家被 matchmaking 分到【不同房间】，于是一直等第二人（服务器日志可见多个 onJoin 都是 1/2）
- 修复：① 重启服务器清空残留房间 ② MyRoom 新增 cleanupStalePlayers()（onJoin 时对比 this.clients，删除已断开却仍在 state.players 里的僵尸座位，并在人数不足时重置房间状态）③ initGame 加 try/catch + onJoin 打印房间人数/gameStarted
- 前端诊断增强：未开局时显示"⏳ 等待对手加入…（房间 N/2 人）"与"🔑 房间号 xxxxxxxx · 两个页面需一致"；日志打印 roomId、房间人数变化；5 秒未开局自动输出排查提示
- 排查要点：两个页面必须显示同一个房间号才会开局；否则说明被分到不同房间（有僵尸残留），关闭所有旧页面重开或重启服务器

## 2026-10-23 行动区改为「临时离场」：技能结算完立刻回到手牌
- 用户反馈：打出的牌进入行动区后永远回不到手牌，导致下一夜无法再次使用（行动区只进不出）
- 根因：playCard 只有 hand.splice → play.push，全文件没有任何回收逻辑；行动区前身是"战场"，设计为永久存放
- 规则变更：行动区 = 外出执行任务的【临时区】，本次行动结算完毕 → 牌立刻回到手牌，下一阶段可再次打出。这也解释了为什么行动区的牌仍算存活（它只是临时离场）
- MyRoom：新增私有字段 pendingCardId / pendingCardIndex（记录待回收的牌及其原位）；新增 returnCardToHand(sessionId, cardId, insertAt) 插回原位；新增 takePendingCard() 取出并清空
- 三处回收时机：① chooseTarget 的 wolfKnife/witchPoison 分支（技能生效后）② index === -1 跳过技能（技能作废照样回收）③ playCard 末尾（无主动技能的牌，如白天出的平民，出牌动作即任务完成）
- 额外修复：startPhase 的超时回调加兜底——若仍卡在 pendingAction，自动 clearPendingAction + 回收牌再 advancePhase，避免有人不操作导致整局永久卡死
- 前端：行动区 tag 改为「临时离场 · 用完即回手牌」；新增 cardReturned 消息处理 + @keyframes cardReturn（牌回手时上浮高亮 0.7s，提示未被消耗）；diff 日志加「↩️ 任务完成，回到你的手牌（可再次打出）」
- 测试 18 个全过（新增"技能结算完→回到手牌，可再次使用"含跨夜二次打出、"白天出平民立刻回手"；同步修正 HUNTER/CASCADE 用例中因牌插回原位而变化的取牌下标）
- 真实服务器双客户端验证：出牌后 行动区1/手牌5 → 刀完后 行动区0/手牌6 ✓
