# 项目长期备忘

## 用户的 UI 偏好（务必遵守）
- **极简信息密度**：只保留核心交互所需信息（选牌/用牌/墓地）。凡"解释显而易见之事"的文字一律删除。
- **卡面设计**：卡牌只显示 图标 + 名称，不要类型小字（神牌/狼人）、不要重复名称的技能标签，以后也不需要这类冗余设计。
- **禁止任何说明性角标/注释性 UI**（2026-11-01 明确要求）：不要为"这张牌能干嘛 / 状态变化了"在卡面加角标、胶囊、小字提示（如盗贼的「🔀 夜·换牌」）。状态变化玩家自己看得到，不需要 UI 解释。
- **不要写游戏文案解释**（2026-11-01 明确要求）：横幅/按钮只留动作名 + 必要数字，不写"请在下方点击选择""等待对方完成操作"这类说明句。已删：图例「彩色=可行动 灰色=不可行动」、流放按钮「（满足条件）」「（需本夜死过牌）」。
- **设计别过度保守**（2026-11-01 明确要求）：不要为了"防呆"给玩法加限制。用户原话"这是在做游戏，而不是写文案"。已放开：盗贼可换走对手的盗贼；可换走已被刀/毒锁定的牌（死亡跟着牌走）。
- **零光污染**：不要任何 box-shadow/text-shadow 发光、脉冲、呼吸、无限循环动画。
- 不显示先手/后手/P1/P2 等元信息。
- 提示类 UI 去重：同一信息只保留一个出口（如回合提示只保留一次性弹窗，不要常驻横幅；技能入口只留点牌触发，不要额外科按钮）。

- **玩法数值/效果逐项问**（2026-11-01 明确要求）：凡是"每个角色/每张牌的效果差异"这类设计题（如奇迹商人对各神职的强化），必须**逐条列出来问用户拍板**，不要自己替他决定。可一次性给选项让他选，但决定权在他。

## 技术要点
- Colyseus 0.18 + Schema v5（schema()/t API）；手牌与墓地走 HAND_VIEW_TAG 私有视图。
- 本机设了 http_proxy=127.0.0.1:58566：curl 本地服务必须加 --noproxy '*'，否则误判 502。
- 启动服务用托管后台任务 `npm start`（tsx watch 热重启），不要在一次性命令里 & 启动（会被回收导致网页打不开）。
- 测试：npx mocha -r tsx "test/**.test.ts" --exit --timeout 15000
