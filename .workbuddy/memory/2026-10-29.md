## 2026-10-31（续7）排障：本地网页打不开 —— 服务进程被回收 + 代理干扰诊断
- 现象：用户反复遇到 localhost:2567 打不开（"又"无法打开）。
- 根因①（主因）：之前我用 `(npx tsx src/index.ts > log 2>&1 &)` 在【单次 Bash 调用内】后台启服务，
  该调用结束后子进程被回收 → 端口无人监听 → 浏览器打不开。改代码后我还手动 kill 旧进程，更容易出现空窗。
- 根因②（干扰诊断，非故障）：环境里设了 http_proxy/HTTP_PROXY=http://127.0.0.1:58566，
  导致 `curl http://localhost:2567/` 走代理返回 502（假象）。必须用 `curl --noproxy '*' http://localhost:2567/`
  才能测到真实状态（浏览器默认对 localhost 绕过代理，所以只影响我的检查）。
- 修复/优化：改用【Bash 工具的 run_in_background 托管后台任务】启动 `npm start`（= tsx watch，改文件自动重启），
  进程不再随单次调用结束被杀；task_id=prMjXt。验证：`curl --noproxy '*' localhost:2567` → HTTP 200，
  且页面已含 mode:"revive" / me.graveyard / 从自己墓地复活。
- 经验（后续必守）：① 起服务一律用 run_in_background=true 的托管后台任务，不要用 `&`+子shell；
  ② 校验本地服务一律加 `--noproxy '*'`；③ 用 npm start(watch) 而非一次性 tsx，改完代码用户刷新即可。
